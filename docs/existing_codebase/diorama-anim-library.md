# Diorama anim library

Holds every character animation in the game as GDScript keyframe tables and compiles them into `AnimationLibrary` resources at runtime, per rig. It is on the live play path: `DioramaAnimController._finish_bind` calls `build_library()` for every player, enemy, boss, and training dummy (`diorama_anim_controller.gd:89`). There are no authored `.anim`/`.tres` animations and no imported animation data — the six `.res` files under `apps/game/client/assets/animations/diorama/` are themselves generated by running these same tables through the exporter (`scripts/tools/export_diorama_anim_libraries.gd`).

## Key format

Every key is `[time, x, y, z]`. A part entry may have a `"pos"` channel (meter **offset** from the part's rest position) and/or a `"rot"` channel (euler radians **offset** from the part's rest rotation). `_add_vector_track` writes `rest_value + offset` as the actual keyframe value (`:573`), so clip tables are rig-independent as long as the rest pose is supplied correctly. Locomotion/reaction clips in `CLIPS` use absolute seconds; attack clips in `ATTACKS` use normalized time `0..1` and are stretched at compile time.

## Compilation

`build_library(rest_pose, events_path, profile = "player", force_compile = false)` (`:462-482`):

1. Unless `force_compile`, `_can_use_authored_library(rest_pose, profile)` (`:453-459`) returns `true` when the rest pose contains a `Root` key **and** `AUTHORED_LIBRARY_PATHS[profile]` exists on disk. If so, `ResourceLoader.load()` returns the `.res` and **`events_path` is discarded entirely**.
2. Otherwise every `CLIPS` entry is compiled through `_compile`, then `RESET` is appended.

`_compile(spec, rest_pose, events_path, speed, phase_map)` (`:515-556`):
- Length is `phase_map["total"]` for attacks, else `spec["length"] / speed`, floored at 0.02 s (`:523-524`).
- `loop_mode` is `LOOP_LINEAR` when `spec["loop"]`, else `LOOP_NONE` (`:525`).
- For each part present in the rest pose, `pos` becomes a `<path>:position` value track and `rot` a `<path>:rotation` value track, both `INTERPOLATION_LINEAR` and `UPDATE_CONTINUOUS` (`:566-569`).
- A method track is added **only when `methods` is non-empty and `events_path != ""`** (`:550`).

`build_attack(clip_name, rest_pose, events_path, startup, active, recovery)` (`:486-512`) deep-copies the spec, appends the two hitbox markers, and builds a `phase_map` so `_remap_time` piecewise-linearly stretches normalized time onto the real weapon phases (`:577-596`): `[0, startup_end]` -> `[0, startup]`, `[startup_end, active_end]` -> `[startup, startup+active]`, `[active_end, 1]` -> `[startup+active, total]`. `total` is floored at 0.08 s (`:504`).

## Authored `.res` libraries

`AUTHORED_LIBRARY_PATHS` (`:22-29`) maps six profiles to `res://assets/animations/diorama/<profile>_locomotion.res`. All six files are present on disk. There is **no `dummy` entry and no `dummy_locomotion.res`**, which matches the six exporter entries in `export_diorama_anim_libraries.gd:10-71`.

The exporter calls `build_library(rest_pose, "", profile_key, true)` (`export_diorama_anim_libraries.gd:81`). Two consequences follow directly from that call:

1. `events_path` is the empty string, so `_compile`'s method-track gate at `:550` is never satisfied. **The six `.res` libraries contain no method tracks at all** — no `FOOTSTEP` in `walk`/`run`, no `SWING_VFX` in `parry_success`.
2. `force_compile = true`, so the exporter compiles from the tables rather than re-loading a stale `.res`.

The exporter's `REST_POSES` (`export_diorama_anim_libraries.gd:10-71`) is a hand-written duplicate of the geometry that `_build_humanoid`/`_build_quadruped` produce. Checked value by value against `diorama_character_skin.gd:32-86` and `:365-451`, all six currently agree (for example `melee` `LegL` at `(-0.14, 0.48, 0)` matches `hip_x = 0.14`, `leg.y = 0.48`; `brute` `ArmL` at `(-0.46, 0.7216, 0)` matches `shoulder_x = 0.46`, `torso.y * 0.88 = 0.82 * 0.88`). Nothing in the repo asserts that they stay in agreement.

The exporter rest poses omit `WeaponMount` and `ShieldMount` for all six profiles, and `Shield` for the `shield` profile. Since no clip in `CLIPS` or `ATTACKS` keys those names, the only effect is that the authored `RESET` clip does not reset the mount pivots.

The exact clip list stored inside each `.res` file could not be read directly: the files are binary Godot resources and are not readable by the documentation tooling available here (`Grep` skips binary content, the file reader rejects `.res`). What the exporter would produce is verifiable from code — 17 `CLIPS` plus `RESET`, no method tracks. Whether the on-disk files are current is `ABSENT` from any check: `diorama_anim_suite.gd:16-30` tests only `ResourceLoader.exists()` per profile, never clip names, clip count, track count, or content hash.

## Quadruped gait

`walk` and `run` include `LegBL`, `LegBR`, and `Tail` tracks (`:64-66`, `:85-87`) with a comment marking them quadruped-only. The phasing is a diagonal trot: at `t = 0` in `walk`, `LegL` is at `+0.55` rad and `LegBR` at `+0.55`, while `LegR` and `LegBL` are at `-0.45`.

The amplitudes are the biped values, unchanged. A biped `player` leg is 0.46 m long, so a `+0.55` rad hip rotation moves the foot 0.24 m forward. A hound leg is 0.30 m (`diorama_character_skin.gd:426`), so the same rotation moves its foot 0.16 m. `walk` is 0.8 s long with two `FOOTSTEP` markers, i.e. two steps per cycle and a stride of roughly 0.31 m per cycle for a hound. `content/enemies/frost_hound.json:8` sets `move_speed: 5.5`, so the hound covers 4.4 m per `walk` cycle at `speed_scale = 1.0`. The controller clamps `walk` playback to at most 1.6x (`diorama_anim_controller.gd:159`), so the fastest the cycle can run is 0.5 s and the feet slide roughly an order of magnitude further than they step. The same mismatch applies to bipeds: the player at `WALK_SPEED = 4.5` (`locomotion.gd:3`) travels 3.6 m per 0.8 s cycle against a 0.48 m stride.

`walk` also bakes a constant `+0.06` rad forward torso lean into all three keys (`:56`), and `run` a constant `+0.2` rad (`:78`), so the torso pitch snaps on entering and leaving those clips rather than easing.

## Contracts

- **Part names keyed by clips** — `Root`, `Torso`, `Head`, `ArmL`, `ArmR`, `LegL`, `LegR`, `LegBL`, `LegBR`, `Tail`, `Bow`. `WeaponMount`, `ShieldMount`, `Shield`, `EarL`, and `EarR` are never keyed by any clip.
- **Rest-pose shape** — `{ part_name: { "path": String, "position": Vector3, "rotation": Vector3 } }`, produced by `DioramaCharacterSkin.collect_rest_pose` (`diorama_character_skin.gd:222-227`).
- **Method names** the host must implement: `anim_hitbox_on`, `anim_hitbox_off`, `anim_swing_vfx`, `anim_footstep`.
- **Consumers** — `DioramaAnimController` (`:89`, `:295`, `:253`, `:273`, `:281`), `diorama_character_rig_player.gd:34`, `export_diorama_anim_libraries.gd:81`, `diorama_anim_suite.gd:19-40`.
