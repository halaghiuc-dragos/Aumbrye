Everything here survived the retirement of three point-in-time audit artefacts that used to sit at
the repository root:

| Retired artefact | What it was | Why it went |
|---|---|---|
| `REFACTOR_OPTIMISE_BUGFIX.md` | 4,020-line backlog, static analysis of commit `3e22117`, dated 2026-08-06 | 187 of its 209 items carried an inline `RESOLVED` marker; the 22 unmarked headings were 19 section titles and the 3 `REF-` items below |

The three files described a tree that no longer exists. This document holds only what is still
true, and is meant to be edited in place as items land — not regenerated.

For the *shape* of the repository (counts, autoloads, suites, content categories), see
`project_structure.json`, which is generated by `tools/generate_project_structure.py` and should be
re-run rather than hand-edited.

## 1. Structural — accepted debt with a known shape

### R-01 — 28 autoloads form an unbounded global mutable graph
*(was `REF-01`; the count was 27 when first written)*

`project.godot` registers 28 autoload singletons. Every one is globally reachable and mutable from
every script, initialisation order is implicit, and there is no dependency graph. `RunFlow` alone
touches saves, scene routing, procgen, the cloud API, leaderboards, achievements, buffs and respawn
rules. A `GameFacade` autoload exists, which suggests a consolidation was started and abandoned.

**Direction** — group autoloads into 6–8 owned subsystems behind explicit facades, and split
`RunFlow`.
**Where** — `apps/game/client/project.godot` (`[autoload]`), `scripts/app/run_flow.gd`,
`scripts/app/game_facade.gd`

### R-02 — The dungeon generator is implemented twice, in two languages
*(was `REF-02`, and `project_analysis.json` entry 18)*

There is a full C# generator in `packages/procedural/` and a full GDScript generator in
`apps/game/client/scripts/dungeon/procgen/`. They must produce identical output for a given seed,
and the only thing holding them together is `cross_stack_parity_suite.gd`. Every balance or layout
change has to be made twice, correctly, in two languages.

This is currently an *accepted* split rather than an oversight — `docs/ADR/0002-procgen-authority-split.md`
records the contract and the path to closing the gap, and `DungeonGenerator.cs` points at it. The
debt is real regardless.

**Direction** — make C# authoritative and have the client consume a generated deterministic layout
artefact instead of reimplementing the algorithm.
**Where** — `packages/procedural/**`, `apps/game/client/scripts/dungeon/procgen/**`,
~~`apps/game/client/scripts/validation/suites/cross_stack_parity_suite.gd`~~ (removed — §119)

### R-03 — Three parallel representations of the same character art
*(was `REF-05`; partially reshaped since it was written)*

Character geometry still exists three ways: `.vox` authored sources in `art-source/` (262 files),
baked meshes in `apps/game/client/assets/characters/` (40 files), and `.voxels.json` runtime data
(181 files) that `VoxelMeshBuilder` greedy-meshes at load.

What changed since the original write-up: the baked meshes were `.mesh` files in Godot 3 text
format, which Godot 4 could not load at all — they have been re-baked to valid `.tres` and every
reference repointed. The *duality* remains: `VoxelMeshBuilder.baked_mesh_path()` still prefers a
baked sibling when one exists, and `tools/voxel-import/` is a second, stale pipeline (see M-01).

**Direction** — pick one runtime representation and generate it from `.vox` under test.
**Where** — `art-source/characters/**`, `apps/game/client/assets/characters/**`,
`apps/game/client/scripts/art/characters/voxel_mesh_builder.gd`

### R-04 — Validation suites are a large surface
*(was `project_analysis.json` entry 37, recorded there as "bloat")*

58 suites, ~27,000 lines. The original entry called this bloat and proposed deleting it. That
judgement is not adopted here: the harness is the only thing that makes cross-stack parity, save
migrations and seeded procgen verifiable, and it has repeatedly been the thing that caught real
defects. Recorded so the earlier recommendation is not silently lost, and flagged as **not
actionable as written**.

The genuinely unused part is the diagnostic scratch scripts — `~~scripts/tools/_diag_keys.gd~~ (never committed)` and
`~~scripts/tools/_diag_settings.gd~~ (never committed)` — which no workflow references.

## 2. Deliberate deferrals — documented in code, left as-is on purpose

### R-05 — `SeededRandom.NextInt` uses biased modulo reduction
The bias is below one part in 2^40 for any range under a million, and the type's own remarks
declare it "intentional and contractually frozen": it is the simplest reduction to reimplement
identically in GDScript, and the golden sequences in `SeedReproducibilityTests` pin it. Switching to
Lemire multiply-shift is a real improvement but only as a coordinated change landing in both
languages in the same release with regenerated goldens.
**Where** — `packages/procedural/Random/SeededRandom.cs`

### R-06 — `RunFlow._cloud_finalize_run` is fire-and-forget
Called without awaiting so a slow or dead server cannot stall the death/escape flow. The tradeoff
is that a failed finalisation is invisible to the player. Intentional; revisit if cloud runs become
load-bearing.
**Where** — `apps/game/client/scripts/app/run_flow.gd`

### R-07 — Server-authoritative runs are stubbed and disabled
`USE_ONLINE_PROCgen` is hardcoded `false`; `_try_online_generate` exists behind it. Tracked in
`docs/ROADMAP-online-runs.md`.
**Where** — `apps/game/client/scripts/app/run_flow.gd`

### R-08 — OAuth (Google/Discord) deferred to post-EA
The account page says so in user-visible copy. Tracked in `docs/ROADMAP-account-recovery.md`.
**Where** — `apps/web/src/pages/Account.tsx`, `services/backend/.../AuthService.cs`

### R-09 — Synchronous content JSON loads on first use
`WeaponController.load_weapon_from_path` and its equivalents still call `ContentLoader.load_json`
synchronously, so first load and floor transitions can hitch. `ContentLoader` now caches, which
takes the repeat cost off; the first-touch cost remains.
**Where** — `apps/game/client/scripts/combat/weapon_controller.gd`

### R-10 — Steam integration runs in stub mode
The backend half exists (`/api/v1/auth/steam`, `Infrastructure/Security/SteamAuthService.cs`, with the
configured-appId check enforced). The client half does not: GodotSteam binaries are absent, so
`SteamService.is_stub_mode` is `true` and no ticket can be produced. Steam Cloud adoption and
achievements run through the same stub.
**Where** — `apps/game/client/scripts/platform/steam_service.gd`

## 3. Content authoring and tuning — decisions, not repairs
*(reproduced from `GAME_DESIGN_AUDIT.md` §6, which flagged these rather than deciding unilaterally)*

- **Escalating whiff punish (`D3`).** A design addition, not a defect. With the tracking and healing
  changes landed, the fight already reads as read → space → punish; adding a second failure axis on
  an untested baseline would be tuning blind. Worth revisiting after the combat changes are played.
- **Widening the talent tree.** The tree deliberately stops short of the 48-slot ceiling to keep
  builds exclusive. Going past level 40 needs roughly 70+ slots first — content authoring, and
  picking those nodes is a design decision.
- **Per-boss `tracking_fraction` values.** The knob is exposed per attack and per enemy so a
  deliberately relentless boss move stays expressible; every enemy currently runs the 0.55 default.
  Which bosses should deviate is a playtest question.
- **Relic offers outside boss kills.** The offer is hooked to boss defeat, which makes all 24 dark
  relics reachable. Bonfires and floor transitions are equally valid hooks; adding them without
  seeing pacing is a balance decision.
- **New bosses, biomes, encounters.** Content authoring.
- **`_dodge_speed` / `DODGE_SPEED` / `DODGE_BACK_SPEED`.** Left in place: they still derive
  `_is_backstep` and feed `BACKSTEP_SPEED_MULT`. Removing them is a separate cleanup.
- **11 placeholder SFX.** `door_open`, `door_release`, `door_seal`, `footstep_snow`,
  `footstep_stone`, `footstep_water`, `footstep_wood`, `lever_pull`, `lever_unlock`, `portal_enter`,
  `portal_open` are still synthesised tones carrying `"placeholder": true`, and `AudioDirector`
  warns about them on every boot. Needs real foley.
  **Where** — `apps/game/client/scripts/audio/audio_director.gd`

## 4. Found while retiring the old documents

### M-01 — `tools/voxel-import/` is a stale second art pipeline
`godot_mesh_writer.py` emits a Godot 3-era `_surfaces` payload (a positional `arrays` list with
`"primitive": 4`). Godot 4 wants packed `vertex_data`/`index_data` byte buffers and loads that shape
as an *empty* mesh. Separately, `cli.py` and `convert.py` write rig manifests pointing at baked
meshes, while the live manifests under `content/characters/` reference `.voxels.json` produced by
`tools/generate_character_voxels.py` — so running the old pipeline would regress them.

The committed `.tres` meshes were baked through Godot itself, not by this writer. Either rewrite the
serializer against the Godot 4 surface format or delete the pipeline; leaving it is a trap.
**Where** — `tools/voxel-import/godot_mesh_writer.py`, `cli.py`, `convert.py`

### M-02 — A content JSON read fails on every harness run
`ContentDirLoader._load_directory` → `ContentLoader.load_json` produces
`Parse JSON failed. Error at line 0` while `ItemCatalog` loads. Every file under `content/` parses
standalone, none are empty and none are unreadable, so something in the directory walk is handing
the parser an empty string. Harmless today because the entry is skipped, but it means one item file
is silently not in the catalogue.
**Where** — `apps/game/client/scripts/content/content_dir_loader.gd`,
`apps/game/client/scripts/app/content_loader.gd`

### M-03 — The headless harness can segfault in a long full run
A full `validation_main.gd` run crashes with SIGSEGV inside `SettingsSchema._monitor_option_labels`
→ `DisplayServer.screen_get_usable_rect()`. It does not reproduce when the suite is run alone, only
after a long sequence of preceding suites, and the C++ backtrace shows a repeating frame pattern
consistent with stack exhaustion rather than a display-server fault. Needs isolating before the
harness can be trusted as a single-command gate.
**Where** — ~~`apps/game/client/scripts/validation/validation_runner.gd`~~ (removed — §119),
`apps/game/client/scripts/app/display_service.gd`

### M-04 — Local procgen emits secret edges whose rooms are not in the definition
With the validator's schema-version check corrected (it was pinned to `1` while the generator and
`content/schemas/dungeon-definition.v2.json` both say `2`), `LocalProcgen.generate()` still fails
for every biome — now on `edge_endpoints_exist`.

Reproduction: `DungeonProcgen.generate("forgotten_castle", 42001, 1, 1, 1, false, false)` returns
17 rooms with ids `arena, boss, combat_3..combat_11, courtyard, entrance, hall, obstacle, stairs,
treasure`, and 21 edges — two of which are `combat_10 -> secret_17` and `combat_11 -> secret_18`.

Cause: `RoomGraphGeometry.build_edges()` skips `SlotType.SECRET` in its main loop, then a second
loop over `graph.secret_ids` appends one `{"kind": "secret"}` edge per secret room.
`build_rooms()` iterates `assignment["rooms"]`, which never contains secret slots, so those
endpoints have no room. `DungeonDefinitionValidator` then rejects the whole floor, `LocalProcgen`
burns all three seed salts and returns `ok: false`.

Which side is wrong is a design question and was **not** guessed at here — secrets are also tracked
as placements (`placements.secrets`, `RunFloorConfig.count_secrets()`) and as a reserved minimap
kind, so they may be deliberately not rooms. Either `build_edges` should not emit those edges, or
`build_rooms` should include secret slots, or the validator should exempt `kind == "secret"`.

This is why nine `procgen.biome.*_generates` / `dungeon.biome.*_build` assertions fail in the m6
suite. Since `USE_ONLINE_PROCgen` is `false` (see `R-07`), local generation is the only generator.
**Where** — `apps/game/client/scripts/dungeon/procgen/room_graph_geometry.gd`,
`apps/game/client/scripts/dungeon/dungeon_definition_validator.gd`

### M-05 — Open validation failures in the `m6` suite
Beyond the procgen cluster above, running `--suite=m6` leaves these failing. They were not
investigated in the pass that produced this document:

- `content.items.catalog_cap` — the catalogue holds 221 items against a hardcoded cap of 84. The
  cap looks stale rather than the content wrong; confirm the intended ceiling and update the
  assertion in `m6_suite.gd`.
- `m6.balance.export_schema` — `reports/balance_export.json` does not match `balance-export.v1.json`.
  Likely just needs regenerating via `tools/balance-export.mjs`.
- `ui.skin.no_label_walk` — `apply_pixel_theme` themes an arbitrarily-named `Label` by type rather
  than by node name.
- `ui.skin.button_sfx_coverage` — some hub menu scripts do not go through `GameUISkin.make_button`.
- `display.relayout_on_change`, `display.window_size_fallback`.
- `death_visual.dummy_dissolves` (in the `death_visual` suite) — training dummy meshes do not carry
  the dissolve saved-override meta after death.

Note that `runner.coverage_*` and `suite.leaked_node_*` failures are artefacts of running a single
suite with `--suite=`; they are not defects.

## How this was verified

Every claim retired from the three source documents was checked against the working tree rather
than taken on the document's word:

- The two markdown documents self-annotate. `REFACTOR_OPTIMISE_BUGFIX.md` carries an inline
  `RESOLVED <date>` marker on 187 of 209 item headings; `GAME_DESIGN_AUDIT.md` has a §5 "What was
  implemented" and a §6 "Not implemented, and why". Only the unmarked residue was carried forward.
- `project_analysis.json` had no status field, so its 67 entries were checked individually against
  the paths each names — middleware ordering and forwarded-header restrictions in `Program.cs`,
  `TrimAsync` rank direction, run-completion concurrency claiming and floor bounds in `RunService`,
  `SteamId` value conversion, display-name retry, save quarantine-on-corrupt, `ExecuteDeleteAsync`
  token cleanup, bounded dungeon caches, zero-weight guards in `AffixRoller`/`EnemyPlacer`,
  single-pass canonical serialisation, leaderboard account-keyed members and persisted elapsed time,
  httpOnly refresh cookies, `sessionStorage`-backed reload guards, clamped URL parameters, combined
  abort signals, generated `schema.d.ts`, collapsed v1/v2 content schemas, attack-token release paths,
  hurtbox hyperarmor, line-of-sight masks, boss HUD unbind disconnects, floor-restart snapshots and
  numeric cloud-save timestamps. All were found fixed. The residue is sections 2 and 4 above.
