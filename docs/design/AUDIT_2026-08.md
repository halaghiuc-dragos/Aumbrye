## 2. Combat — Soulslike Feel

### 2.1 Commitment (highest impact)

| Problem | Action | Location | Tool / Tech |
|---------|--------|----------|-------------|
| Attacks are cancellable by anything — no weight | Lock movement and input through startup + active; allow dodge only in a late recovery window | `weapon_controller.gd:173-188` | GDScript state gate; drive from `AttackPhase` |
| Full move speed while swinging | Cut to ~20% during startup/active, restore in recovery | `locomotion.gd:82-98` | reuse `set_speed_multiplier()` |
| No turn cap while attacking | Clamp facing rotation during startup/active | `locomotion.gd:111-113` | `lerp_angle` with a per-phase max delta |
| Recovery is not felt — no whiff punish | Explicit recovery lock, longer on heavies | `weapon_controller.gd:182-187` | JSON `recovery` already exists; enforce it |
| Movement fully code-driven, animations cosmetic | Move attack lunges into animation-driven displacement | `dodge.gd:151-160` | `AnimationPlayer` position tracks on the root pivot |

### 2.2 Defence

| Problem | Action | Location | Tool / Tech |
|---------|--------|----------|-------------|
| Block is a tap with a fixed 0.65s window — no hold | Add a hold-to-block state with per-hit stamina and chip damage | `guard.gd:39-65` | extend `GuardState` enum |
| Mistimed parry = full damage (no block during the parry window) | Make the parry window a subset of an active block state | `guard.gd:52-56`, `:95-99` | — |
| Parry only staggers — no payoff | Add riposte: critical-damage prompt window after a successful parry | `guard.gd:110-119` | `Area3D` prompt + `play_attack` clip |
| No backstab / positional crit | Rear-arc damage multiplier | `hurtbox.gd:30-51` | dot product vs victim facing |
| Parry is a single-frame check at enemy attack start | Test parry overlap continuously during the enemy's active frames | `castle_enemy_base.gd:497-514` | move the check into `Hitbox._try_hit` |
| Projectiles can only be dodged, never blocked | Route projectile hits through `modify_incoming_hit` | `enemy_projectile.gd:16-51` | — |

| Problem | Action | Location | Tool / Tech |

## 10. Suggested Order

1. **P0 bugs.** Generation fill/validation conflict and seedless fallback; bow softlock; poise `_broken`; talent tree granting nothing. Four fixes that change what the game actually is.
2. **Test gaps that hid them.** Layout variation assertions, `used_fallback` check, content schema rules, Godot suites in CI.
3. **Stat vocabulary.** Unify `STAT_KEYS` across talents, items, and weapons — everything in §5 depends on it.
4. **Combat commitment pass** (§2.1). Largest feel win per hour of work.
5. **Audio pass** (§8). Bus layout plus combat SFX is the single biggest perceived-quality jump; the game is currently silent in combat.
6. **Layout structure pass** (§3.1). Critical path, pacing beats, remove blob fill.
7. **Class + starting weapon** (§5). Gives runs identity and makes the talent tree meaningful.
8. **VFX finish** (§7.1 P3/P4). Ribbons, decal telegraphs, real status icons.
9. **Story foundation** (§4.1). Story bible before any narrative content authoring.
10. **Architecture debt** (§9.2). Split `RunFlow`, reduce autoloads, pick one generator.
